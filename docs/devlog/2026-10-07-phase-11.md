# 2026-10-07 — Phase 11 — v0.12.0

## What changed

Implemented client-side auth state and hardened every auth form's UI.

Added `AuthProvider`/`useAuth()` (`apps/web/src/components/auth-provider.tsx`)
with explicit `loading`/`authenticated`/`unauthenticated`/`error` states,
seeded from a new server-resolved session helper
(`apps/web/src/lib/session.ts`, called from the root layout) so first paint
never shows a loading flicker, a flash of protected content, or a flash of
the login page for an already-authenticated user. A session-generation
counter plus a per-request `AbortController` (and a new
`ApiClientAbortedError` in `@saas/api-client`) drop and cancel a stale
`/auth/me` response that arrives after logout or a user change. Added
cross-tab login sync (`broadcastLogin`/`onLoginBroadcast`, mirroring the
existing logout broadcast) and centralized logout in
`AuthProvider.logout()`, which clears every registered cache (sessions
list, connected-accounts list) on any tab's logout, not just the
initiating one.

Hardened all six auth forms (login, signup, otp, forgot-password,
reset-password, verify-email): added a `submitLock` double-submit guard
where it was missing (forgot-password, signup, reset-password,
verify-email); added two new shared components, `ErrorSummary`
(role="alert", aria-live="assertive", focused on a new error) and
`PasswordInput` (visibility toggle that preserves the typed value/cursor
by swapping the `type` attribute on the same DOM node, `aria-pressed`);
fixed `forgot-password`'s missing `autoComplete="email"` and a dead
`<FormError />` with no `message` prop; bumped the shared `Input`/`Label`
font size to 16px (prevents iOS Safari's auto-zoom-on-focus, relevant to
the 360px-viewport checklist item); added `role="status"`/`aria-label` to
loading indicators.

Added `tests/e2e/auth-ui.spec.ts` (Playwright + `@axe-core/playwright`)
and **actually ran it against a live `next dev` server** — the first time
this workstream has live-browser-tested anything beyond Phase 2's
homepage smoke test. This surfaced three real, previously-undetected
bugs, all fixed this phase:

- **BUG-022**: `.js`-suffixed relative imports in `packages/ui`/
  `packages/config` (valid under Node's own ESM loader, used correctly by
  `tsx` in apps/api/apps/worker) failed to resolve under `next dev`
  specifically, returning a 500 on every route in apps/web. Invisible to
  `next build` and to every unit/integration test, since none of them
  boot `next dev`.
- **BUG-023**: the cookie-consent banner rendered outside any landmark
  region, failing axe's "region" rule (moderate impact) on every page.
- **BUG-024** (the most significant finding): a wrong login password,
  wrong OTP code, or expired/used magic link all legitimately return HTTP
  401 for reasons unrelated to session validity, but the shared API
  client treated every such 401 as "session expired" and fired a hard
  `window.location.href` redirect before the calling page's own error
  handling could run — caught by this phase's own "login error summary
  receives focus" test. Fixed with an explicit opt-in
  `treatUnauthorizedAsOrdinaryError` flag at the three real call sites.

## Why

The task's own checklist (26 items: loading states, double submission,
error display, password visibility, accessibility, focus management,
race conditions, flash-of-content/flash-of-login) is a UI-correctness
checklist, and this workstream's established discipline has been to
actually run what can be run rather than claim coverage from code review
alone. Standing up a real Playwright+axe run against these specific pages
(not just the homepage) is what caught three real bugs that five prior
phases of unit/integration testing structurally could not have caught —
none of them boot a browser.

## Open issues

- No live Postgres/reachable API: the 2 skipped e2e tests, plus every
  structural item with no automated test this phase (form-reset-on-error,
  autofill, password manager compatibility), are **Requires manual
  verification**, not Confirmed working.
- No real screen-reader software was used — axe and explicit ARIA
  assertions confirm correct markup, not actual announced output.
- `POST /auth/change-password` has the identical BUG-024 shape but no
  frontend UI exists yet to call it — flagged as a Potential risk for
  whoever builds that UI.
- 13 more files repo-wide share BUG-022's `.js`-extension pattern
  (`packages/auth`, `packages/database`) — currently harmless (not
  imported by apps/web/apps/admin today), flagged as a Potential risk if
  that ever changes.
- **Process finding**: discovered that Phase 10's own commit (`a7a54f5`)
  had accidentally absorbed unrelated, unreviewed content into
  `docs/auth/FINDINGS.md` from a separate, concurrent session's
  uncommitted work, because that file was staged as a whole without
  checking for intermixing first. Already pushed; not rewritten here —
  reported directly to the user. This phase isolated its own shared-file
  edits (`docs/TRACEABILITY.md`, `docs/auth/FINDINGS.md`,
  `packages/config/src/index.ts`) by hunk before staging to avoid
  repeating it.
- Several apps/web routes are now server-rendered on demand rather than
  statically prerendered (the root layout's session resolution makes
  every page request-dependent) — a deliberate correctness tradeoff, not
  a regression, flagged for a future performance-focused phase.
- Carried forward: the remaining open architecture questions from Phase 1,
  and D6 (TOTP MFA, still unresolved/unimplemented).
