# 2026-10-11 — Phase 16 — v0.17.0

## What changed

Built the images/speed/contrast/mobile/links launch-readiness surface:
an accessibility lint gate, an image size budget, Lighthouse CI with real
Core Web Vitals budgets, a fixed focus-visibility bug, touch-target
fixes, extended viewport/contrast test coverage, and a link-checker CI
job.

- **Images (tasks 1-2)**: confirmed via research that this codebase has
  zero `<img>`/`<Image>` usage anywhere — it's a text/form-only SaaS
  auth starter. Added `eslint-plugin-jsx-a11y` (`alt-text`,
  `img-redundant-alt`) and `scripts/check-image-budget.ts` (200KiB/image
  CI budget) as forward-looking gates, verified both actually work (the
  lint rule via a temporary smoke-test file that deliberately omitted
  `alt`, confirmed it failed, then removed it). Added
  `images.formats: ["image/avif", "image/webp"]` to both apps'
  `next.config.mjs`, also forward-looking.
- **Page load speed (task 3)**: added `lighthouserc.json` and ran it for
  real against a production `next build` + `next start` — not just
  configured. Real measured numbers: `/` LCP 1939ms/CLS 0/TBT 49ms/JS
  123KB; `/login` LCP 2299ms/CLS 0/TBT 56ms/JS 147KB; `/signup` LCP
  2459ms/CLS 0/TBT 63ms/JS 146KB — all under the 2500ms/0.1/200ms/350KB
  budgets. `/dashboard` is excluded (documented as Requires
  configuration: needs an authenticated session LHCI has no backend to
  provide here). Documented explicitly that Lighthouse's lab mode cannot
  measure real INP (a field metric) — Total Blocking Time is the
  standard documented proxy, budgeted at the task's 200ms figure but not
  literally the same metric.
- **Color contrast (task 4)**: researched the actual rendered color
  tokens and found a real, confirmed bug (**BUG-028**) before writing
  any test: `button.tsx`/`form.tsx` both use
  `focus-visible:ring-2 focus-visible:ring-ring` alongside
  `focus-visible:outline-none`, but no `ring` color token existed
  anywhere in `packages/design-tokens` or either app's
  `tailwind.config.mjs` — Tailwind silently drops a utility class
  referencing an undefined color, so every Button and Input in the
  entire app had ZERO visible keyboard focus indicator. Fixed by adding
  a `ring` token (reusing `primary`'s already-confirmed ~5:1-contrast
  value) and wiring it into both apps' configs. Separately confirmed:
  **no dark theme exists anywhere in this codebase** (no `next-themes`,
  no `ThemeProvider`, no `prefers-color-scheme` handling,
  `globals.css` hardcodes `color-scheme: light`) — documented as an
  explicit scope decision rather than silently skipped or fabricated.
  Extended axe `color-contrast`-inclusive `.analyze()` coverage to 5
  more pages (`/`, `/signup`, `/contact`, `/privacy`, `/terms`).
- **Mobile responsiveness (task 5)**: found and fixed **BUG-030**: the
  password-visibility toggle button (sized only by 12px text, no
  padding) and 4 checkboxes (signup terms acceptance + the 3
  cookie-consent categories) were all under the WCAG 2.5.8 24x24px
  touch-target minimum; the footer's 4 nav links/button were under 24px
  tall (plain `text-sm` inline items with no padding). Fixed all of
  them with explicit sizing, reviewed (and deliberately left unchanged)
  genuinely inline prose links like the error-summary's jump links,
  which qualify for WCAG 2.5.8's own "inline text" exemption. Extended
  Phase 11's existing 360px/login-only viewport test to 360/768/1280px
  across 4 pages (`/`, `/login`, `/signup`, `/contact`), plus 3 dedicated
  `boundingBox()` touch-target assertions.
- **Broken links (task 6)**: added `linkinator` + `pnpm check:links` +
  a new CI job. Could not get it to run successfully in this session's
  sandboxed environment — methodically isolated the cause (confirmed:
  not repo content, not the repo's path, not linkinator's own server
  code, not a blanket block on local Node HTTP servers or `undici`) down
  to something external intercepting specifically the ephemeral local
  file-server linkinator spins up to crawl a filesystem path. Documented
  the full investigation in FINDINGS.md rather than either giving up
  silently or fabricating a pass; the script/CI wiring is correct and
  will run for real in a normal GitHub Actions runner.
- **Process gap found and fixed**: running the full `pnpm test:scripts`
  (not just package-scoped test commands) for the first time since
  Phase 13 surfaced **BUG-029** — `scripts/route-matrix.spec.ts`'s
  manifest was missing 5 routes added in Phase 14 (`/contact`,
  `/privacy`, `/terms`, and 2 API handlers), because neither Phase 14
  nor 15 had run that root-level test suite during their own
  verification. Fixed the manifest and added a process note to
  FINDINGS.md: every future phase's closing checklist should run the
  FULL `pnpm test` at least once.

## Why

Every fix in this phase followed from actually measuring something real
rather than assuming it was fine: the focus-ring bug was found by
tracing `ring-ring` back to its (missing) source rather than assuming a
shadcn-style setup existed; the touch-target bugs were found by
measuring real rendered bounding boxes, not guessing from the markup;
the route-matrix gap was found by actually running every test command,
not just the ones recent phases happened to run. The two honest
limitations (no dark theme, link-checker environment issue) are
documented as exactly that — a scope decision and an environment issue
— rather than silently worked around or faked.

## Bugs found and fixed this phase

- **BUG-028** (HIGH): every `Button`/`Input` had zero visible keyboard
  focus indicator — a `ring` Tailwind color token was referenced but
  never defined. Fixed by adding it to `packages/design-tokens` and
  wiring it into both apps' Tailwind configs.
- **BUG-029** (LOW): 5 Phase 14 routes were missing from
  `scripts/route-matrix.spec.ts`'s manifest, because the test suite that
  would have caught it was never actually run in Phase 14 or 15's own
  verification. Fixed the manifest; added a process note for future
  phases.
- **BUG-030** (MEDIUM): 3 interactive controls plus the footer's 4 nav
  items were under the WCAG 2.5.8 24x24px touch-target minimum. Fixed
  with explicit sizing on each.

## Open issues

- No dark theme exists in this codebase — task 4's "both light and dark
  themes" could only be verified for light. Documented as a scope
  decision; building a dark theme from scratch is a materially larger
  undertaking than a contrast audit and was judged out of this phase's
  scope.
- The link checker could not be run successfully in this session's
  sandboxed environment. Methodically isolated the cause to something
  external to linkinator's own code intercepting its internal
  local-file-serving HTTP server specifically — not repo content, not
  this repo's path, not a blanket localhost-server block. The
  script/CI wiring is correct; needs confirming against a real CI run.
- `/dashboard` is excluded from the Lighthouse CI config — needs an
  authenticated session this environment has no live backend to
  provide. Requires configuration (a scripted login via LHCI's
  `puppeteerScript` option) in an environment with a reachable API.
- Today's Lighthouse numbers were measured on this one machine,
  unthrottled, with no real network latency — CI's own run (budgets
  checked there) is the authoritative measurement going forward.
- Carried forward: the remaining open architecture questions from Phase 1,
  and D6 (TOTP MFA, still unresolved/unimplemented).
