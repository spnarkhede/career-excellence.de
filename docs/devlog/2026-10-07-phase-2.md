# 2026-10-07 — Phase 2 — v0.3.0

## What changed

Scaffolded and hardened the secure foundation before any auth-provider code exists:
verified env validation fails loudly (pre-existing, confirmed via test), fixed the
logger's redaction to cover `otp`, added global process-level crash handlers, verified
HTTPS redirect/security headers/CORS with new/existing tests, and added quality tooling
(stricter type-checked ESLint rules, knip, jscpd, madge) wired into CI alongside an
expanded Playwright matrix (Chromium/Firefox/WebKit/mobile) and a new end-to-end CI job.

Along the way, found and fixed five real bugs (see `docs/auth/FINDINGS.md` BUG-001
through BUG-005): a bundle-secret scanner that scanned the wrong directory and would
have failed on every real build; a pre-existing `apps/api` typecheck failure (confirmed
pre-existing via `git stash` bisect) from a `CorsOptions` type conflict, an undeclared
transitive type dependency, and a Prisma `Json` type mismatch; a circular import in
`packages/auth`; and all four auth forms passing an async handler directly to
`<form onSubmit>`, caught by the newly-added `no-misused-promises` rule.

## Why

Per this phase's "GOAL": a running skeleton where configuration mistakes fail loudly
and secure defaults exist before any auth code is written. Most of the actual
scaffolding (env schema, security middleware, CORS, logger) already existed from prior
work in this repo — this phase's job was to verify it against the explicit checklist
and tests, close the real gaps (missing `otp` redaction, missing HTTPS-redirect test,
missing quality tooling), and — per `AUTH_RULES.md` rule 8 ("do not stop at the first
bug") — follow every bug found to its root cause rather than patching the symptom, even
when the bug predated this phase's own changes.
